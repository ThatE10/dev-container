# Paper: write-protected draft + web-only promotion

This directory holds a research draft whose **canonical** source,
[`paper.tex`](./paper.tex), is deliberately hard to change. Agents (and casual
`>`/`sed -i` accidents) can never edit it directly; the canonical file only ever
changes through a GitHub Actions workflow that **you** trigger and a **single-file
pull request** that **you** review and merge in the browser.

Everything below runs on the remote (GitHub) copy. Staged edits reach GitHub
through ordinary commits and pushes — no special CLI steps are required of you.

## Files

| File | Role |
| ---- | ---- |
| `paper.tex` | **Canonical** draft. Write-protected on disk (`chmod a-w`). Promotion-only. |
| `paper.staged.tex` | **Working** draft. This is where all edits actually land. Tracked in git. |
| `paper.md` | Markdown rendering of the canonical draft, regenerated by pandoc during promotion. |

## How the write-protection works (defense in depth)

Four independent layers, so no single bypass exposes the canonical file:

1. **Edit/Write redirect — `.claude/hooks/tex_gate.py`**
   A `PreToolUse` hook on the `Edit` and `Write` tools. When a tool targets
   `paper/paper.tex` it seeds `paper.staged.tex` from the canonical text (if it
   doesn't exist yet, so `Edit` matches apply cleanly), then rewrites the tool's
   `file_path` to `paper.staged.tex` and tells the model the edit was redirected
   and the canonical file is promotion-only. The edit transparently lands in the
   staged file.

2. **Bash guard — `.claude/hooks/bash_guard.py`**
   A `PreToolUse` hook on the `Bash` tool. Denies commands that reference
   `paper/paper.tex` in a mutating context (`>`, `>>`, `sed -i`, `tee`, `mv`,
   `cp`, `rm`, `chmod +w`). This is a **heuristic** tripwire — shell is too
   flexible to catch every case — which is why it is backed by layer 3.

3. **Filesystem bit — `chmod a-w paper/paper.tex`**
   The hard backstop. The file is read-only on disk, so any write that slips past
   the heuristics still fails at the OS level. Git operations reset permissions,
   so a `SessionStart` hook in `.claude/settings.json` re-asserts `chmod a-w` at
   the start of every Claude Code session.

4. **CI isolation — `.github/workflows/draft-isolation.yml`**
   On every pull request: if the changed-file set includes `paper/paper.tex`, then
   every changed file must be within the allowlist `{ paper/paper.tex,
   paper/paper.md }`. This stops the canonical draft from being smuggled inside an
   unrelated PR and makes the promotion PR the only legitimate shape of change.

Ownership is enforced by [`.github/CODEOWNERS`](../.github/CODEOWNERS), which
assigns `/paper/paper.tex` to `@ThatE10` so the promotion PR needs code-owner
approval before it can merge.

## Promotion: staged → canonical

Promotion is the **only** path by which `paper.tex` changes. It is a manual,
browser-driven, reviewed operation:

1. Edit the draft as usual — your changes accumulate in `paper.staged.tex`
   (the redirect and your own edits both land there). Commit and push.
2. In the GitHub web UI: **Actions → "Promote draft" → Run workflow**.
3. The [`promote-draft.yml`](../.github/workflows/promote-draft.yml) workflow:
   - exits early with a "nothing to promote" notice if `paper.staged.tex` is
     identical to `paper.tex`;
   - otherwise copies `paper.staged.tex` over `paper.tex`, regenerates
     `paper.md` with pandoc, creates a `paper-promote/<date>` branch, commits
     **only** `paper.tex` and `paper.md`, and opens a pull request using the
     `PROMOTE_TOKEN` fine-grained PAT.
   - The default `GITHUB_TOKEN` is intentionally **not** used to open the PR:
     PRs created by `GITHUB_TOKEN` do not trigger other workflows, so the
     required `draft-isolation` check would never run and the PR could never
     satisfy branch protection.
4. Review the single-file diff in the browser and **merge**. The new canonical
   draft is published.

## ⚙️ ONE-TIME WEB SETUP CHECKLIST (browser only)

Do this once, entirely in the GitHub web UI. No terminal required.

### 1. Create the fine-grained PAT

1. Go to **GitHub → your avatar (top-right) → Settings → Developer settings →
   Personal access tokens → Fine-grained tokens** →
   **Generate new token**.
   (Direct URL: `https://github.com/settings/personal-access-tokens/new`.)
2. **Token name:** e.g. `dev-container promote-draft`. Set an **Expiration**.
3. **Resource owner:** `ThatE10`.
4. **Repository access:** select **Only select repositories** →
   **`ThatE10/dev-container`**.
5. **Permissions → Repository permissions:**
   - **Contents:** **Read and write**
   - **Pull requests:** **Read and write**
   (Leave everything else at *No access*.)
6. Click **Generate token** and **copy** it now — you won't see it again.

### 2. Save the PAT as the `PROMOTE_TOKEN` Actions secret

1. Go to the repo: **`ThatE10/dev-container` → Settings → Secrets and variables →
   Actions → Secrets** tab → **New repository secret**.
   (Direct URL: `https://github.com/ThatE10/dev-container/settings/secrets/actions/new`.)
2. **Name:** `PROMOTE_TOKEN` (exactly). **Secret:** paste the token from step 1.
3. **Add secret.**

### 3. Add a branch protection rule on `main`

1. Go to **`ThatE10/dev-container` → Settings → Branches → Branch protection
   rules → Add branch ruleset** (or **Add rule** on the classic screen).
   (Direct URL: `https://github.com/ThatE10/dev-container/settings/branches`.)
2. **Branch name pattern / target:** `main`.
3. Enable:
   - **Require a pull request before merging**
     → and check **Require review from Code Owners**.
     (Set **Required approvals** to at least **1**.)
   - **Require status checks to pass before merging**
     → search for and add the **`Enforce canonical-draft isolation`** check (the
     job from `draft-isolation.yml`; it appears in the list after the workflow
     has run on at least one PR — open a throwaway PR first if you don't see it).
4. **Create / Save** the rule.

> After this, the canonical `paper/paper.tex` can only change via a promotion PR
> that (a) is opened by `PROMOTE_TOKEN` so the isolation check runs, (b) passes
> `draft-isolation`, and (c) is approved by you as the code owner — all from the
> browser.
